# API generation

`openapi.json` is the unchanged Castle OpenAPI snapshot identified by `source.json`. The source is https://reference.castle.io/v1/api.json; the snapshot was retrieved on 2026-11-03. Verify its SHA-256 against the metadata when updating it.

Run `go generate ./...` with Go 1.27.3. This prepares a temporary schema from the snapshot, invokes oapi-codegen v2.8.2 with the pinned dependencies in `internal/tools`, generates the root client's policy adapters, and removes the temporary input. It never downloads a newer specification or chooses a newer generator. Dependencies must already be available locally or be fetched at the pinned versions by Go. Commit the generated `api/client.gen.go`, `endpoints.gen.go`, and configuration. Run generation twice and verify the second run produces no changes. To update, download the official specification separately, record its retrieval date and checksum, review upstream changes and the adaptations below, regenerate, and run the tests.

The original schema cannot be generated by oapi-codegen v2.8.2 because `LoginResponse`'s device allOf branch carries conflicting `readOnly` metadata. Preparation removes that branch annotation only. It also removes `context` and `request_token` from the required lists of `RiskRequest` and `FilterRequest`: both schemas' skip flag descriptions and the [official Node SDK conditional payload](https://github.com/castle/castle-node/blob/52bda10f924a5be818c46582e25fb8813e62a175/src/payload/models/risk_payload.ts) permit omission when the respective flag is true. The flag conditions are not enforced by generated types. Skipping token validation prevents risk scores from being calculated. Risk `status` remains required. Filter status is optional in its event variants; generated Go does not apply schema defaults.

All-operation generation also fails on deeply nested JSON Pointer references
with `unexpected reference depth`, first in the IP batch response and then in
aggregation filters. Preparation relocates referenced schema definitions to
named components and rewrites their references, including recursive filter trees.
The exact source pointers and stable component names are checked in at
`internal/cmd/prepareapi/references.go`. No fields are transcribed or flattened;
definitions are copied from the snapshot, including their constraints. Unknown
nested references fail preparation so a schema update requires review.

No operations are filtered out, including HEAD requests and deprecated operations.
The snapshot was checked against the official URL again on 2026-11-05 and was unchanged.

`internal/cmd/generateclient` reads the original specification's success statuses
and media types and the generated `api.ClientInterface` signatures. It generates
root methods that reuse the generated HTTP calls and response parsers. All methods
pass through `response.go` for bounded reads, status checks, safe errors, and
assessment validation. This avoids a fork of oapi-codegen's response template or
hand-maintained endpoint wrappers. Request editors remain a low-level API feature
so root methods cannot override the client's authentication through an editor.

Events declares both JSON and CSV media types. Generated JSON payloads remain
typed; CSV responses remain available as raw bytes in the response envelope.
Bodyless success responses are parsed for headers without interpreting a body.
The dataset's 302 is a successful result carrying a Location, not permission to
follow a redirect with credentials.

The authentication-method changeset description says both endpoints can be null, while its referenced enum is not nullable. Preparation inlines that enum at the two endpoints and makes them nullable, retaining the distinction between omission and explicit null. This interpretation is also consistent with the [official Java SDK's nullable changeset entries](https://github.com/castle/castle-java/blob/ececacaa511fd8f57e10ef45ce4fd72312a31416/src/main/java/io/castle/client/model/generated/ChangesetEntry.java). Request properties retain the schema's extra object level, consistent with the [Java SDK risk model](https://github.com/castle/castle-java/blob/ececacaa511fd8f57e10ef45ce4fd72312a31416/src/main/java/io/castle/client/model/generated/Risk.java). Context headers retain the schema's ordered scalar pairs.

The generated response union preserves unknown fields in its raw JSON; decoding a typed projection can discard fields not known to the schema. Optional scores distinguish missing from zero. Models and low-level endpoint calls are generated; their direct use does not apply the root client's credential and error policies.

The SDK comparisons used these pinned official sources:

- [Node Risk payload and conditional skip flags](https://github.com/castle/castle-node/blob/52bda10f924a5be818c46582e25fb8813e62a175/src/payload/models/risk_payload.ts).
- [Java Risk request and nested properties](https://github.com/castle/castle-java/blob/ececacaa511fd8f57e10ef45ce4fd72312a31416/src/main/java/io/castle/client/model/generated/Risk.java).
- [Java nullable changeset entries](https://github.com/castle/castle-java/blob/ececacaa511fd8f57e10ef45ce4fd72312a31416/src/main/java/io/castle/client/model/generated/ChangesetEntry.java).

Node permits omitted status and loosely typed properties. This SDK follows the
OpenAPI definition's required status and nested request properties instead.
The authentication-method changeset nullability discrepancy remains in the
upstream snapshot; the local adaptation follows its explicit prose.

## Dependency updates

Prefer the latest stable SDK dependencies and generation tools. Keep exact
versions in both Go modules and rerun generation and tests after updates.
As of 2026-11-05, oapi-codegen v2.8.2, runtime v1.8.0, and nullable v1.2.0
are the latest releases. Compatible transitive dependencies are also updated.

The following generator dependencies remain on compatible versions:

| Module | Pinned version | Reason |
| --- | --- | --- |
| `github.com/speakeasy-api/openapi` | `v1.25.6` | v1.26.3 uses `go.yaml.in/yaml/v3.Node` in its overlay API, while oapi-codegen v2.8.2 passes `gopkg.in/yaml.v3.Node`. |
| `github.com/speakeasy-api/jsonpath` | `v0.6.3` | Retains the YAML node types used by the compatible overlay implementation; v0.7.0 switches the YAML dependency chain. |
| `github.com/dprotaso/go-yit` | `v0.0.0-20220510233725-9ba8df137936` | Matches that chain's `gopkg.in/yaml.v3.Node`; newer revisions use `go.yaml.in/yaml/v3.Node` or `go.yaml.in/yaml/v4.Node`. |

These exceptions come from compilation failures against the actual generation
command, rather than assumed compatibility. Revisit them when upgrading
oapi-codegen. They affect the generation tool module, not the SDK runtime.
